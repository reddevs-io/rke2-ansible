—

Keep server and agent plays separate (reject DRY merge)

Merging the two plays in upgrade_rke2.yml into a single play targeting rke2_cluster would make server-before-agent ordering depend on inventory sequence, which is fragile and could break silently if inventory is reordered.
Suggestion #13 downgraded from "merge plays" to "extract shared vars to group_vars/rke2_cluster.yml". The two-play structure stays as the explicit ordering enforcement mechanism. Decided 2026-06-29.
—

Do not auto-uncordon on failure (rescue block emits guidance only)

If a node fails to become Ready after upgrade, uncordoning would let the scheduler place workloads onto a broken node. Leaving it cordoned is the safer default; the gap was operator guidance, not automatic recovery.
Fix #3 reframed: rke2_node_restore gets a block/rescue where the rescue prints an explicit remediation message (node remains cordoned, verify service health, then manually uncordon) and re-raises the failure. No auto-uncordon. Decided 2026-06-29.
—

any_errors_fatal on server play only, not agents

A failed server mid-run risks etcd quorum loss if the next server proceeds; a failed agent is recoverable. Applying any_errors_fatal to both would halt the run on any single agent failure, which is overly strict for worker pools.
Fix #12 sets any_errors_fatal: true on the server play only. Agent play keeps current behavior. Open question flagged for operator in case they want agents to halt-on-first-failure too. Decided 2026-06-29.
