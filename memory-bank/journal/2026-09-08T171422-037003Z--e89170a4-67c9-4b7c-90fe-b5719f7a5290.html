CloudNativePG primary PDB is structurally undrainable

DetailsA cnpg <cluster>-primary PDB pins minAvailable:1 against a selector matching only the single primary pod, so disruptionsAllowed is permanently 0 and kubectl drain of its node can never succeed. Move the primary first by patching .status.targetPrimary (what kubectl cnpg promote does under the hood; the plugin is not installed locally), or upgrade in place. Done for umoja: switched pg-taytu-1 to pg-taytu-4 before zenobia, so the reboot took down only a replica and no failover occurred.
