Recurring patterns and standards. Optional but recommended. Last updated: 2026-06-29 10:22:56

Coding Patterns

Code

Role-based modular structure: each concern (prepare, version_check, node_drain, install, node_restore, agent_join) is a self-contained Ansible role under roles/ with defaults/main.yml + tasks/main.yml.

Code

Control-plane (kubectl) tasks run with delegate_to: localhost / run_once semantics; node tasks run against the target host over SSH.

Code

All tunables exposed as role defaults with conservative production values; overridable via -e, inventory vars, or @vars.yml.

Architectural Patterns

Architecture

Sequential rolling upgrades via serial: 1 — servers first, then agents — to preserve quorum and workload availability.

Architecture

Gated pipeline: a skip_upgrade fact set by rke2_version_check conditionally skips drain/install/restore roles when the target version is already installed.

Architecture

Fail-fast safety: health checks (service active, node Ready, pods running) gate progression to the next node; any failure halts the run.

Architecture

Worker-join flow keeps version parity by auto-detecting the installed RKE2 version from the first server rather than requiring the operator to specify it.

Testing Patterns

Testing

Use --check (dry run) mode to validate the play without making changes; use -v / -vvv for progressive debug verbosity.

Testing

Rollback strategy = re-run the playbook pinning rke2_version to a previous release tag (downgrade path).
