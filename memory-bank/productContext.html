Project Goal

  • Provide a robust, automated Ansible-based workflow for upgrading RKE2 Kubernetes clusters in production with minimal risk and zero cluster downtime.
  • Support sequential, one-at-a-time node upgrades with full health verification between nodes.
  • Extend existing clusters by safely joining new worker (agent) nodes with version parity to the servers.

Key Features

Sequential node upgrades (servers then agents) Skip logic when target version already installed Node cordon + drain with configurable timeouts Post-upgrade health & pod readiness checks System prep (apt update / dist-upgrade / reboot) Add worker nodes playbook (rke2_agent_join) kubectl-driven verification from control node Rollback via pinning rke2_version INI and YAML inventory support

Overall Architecture

Role-based modular Ansible design. Two top-level playbooks: upgrade_rke2.yml (cluster upgrade) and add_workers_rke2.yml (join new agents). Inventory split into rke2_servers, rke2_agents, and rke2_new_agents groups.
Upgrade pipeline = 5 sequential roles per node: rke2_prepare → rke2_version_check → rke2_node_drain → rke2_install → rke2_node_restore. A skip_upgrade fact gates the last three roles when the installed version already equals the target.
Control-node operations (cordon, drain, readiness, uncordon) run against localhost using kubectl; node operations (apt, install, service restart) run over SSH against the target host.
Worker-join flow: preflight validation → auto-detect version from first server → write /etc/rancher/rke2/config.yaml → install agent → enable rke2-agent → optional post-join verification.
